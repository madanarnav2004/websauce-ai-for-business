# Contributing

Make a contribution a business owner can try. A guide should state the task, required inputs, exact steps or prompt, an example result, and what still needs a human check. A skill should solve a repeatable workflow and include a safe example. A cloud or app example should include setup, cost assumptions and a way to verify it works.

Use synthetic names and reserved example domains. Remove private contacts, customer records, API keys, personal messages and unlicensed assets before opening a pull request. Do not copy an entire private project and delete sensitive files afterward; create a clean contribution from reviewed files.

State whether the contribution is a tested, usable module or a proposal. For a Codex skill, validate its `SKILL.md` and try it on the example. For code, run the relevant tests and explain what was tested. Screenshots or performance claims must have evidence and permission to publish.

Questions and corrections are welcome. Please keep issue reports free of real customer data and credentials.
