# Daily inbound run template

This is a prompt template, not an installed schedule. Run it manually or place it in a scheduler that supports your environment. A computer-based Codex schedule needs the host/app and relevant authenticated sessions available.

**Suggested prompt**

> Run one bounded inbound cycle for [business] at [local time and time zone]. Read its current operating rules, content queue, publication receipts and channel ownership. Check new genuine enquiries and comments first. Then work on at most one useful content item from a real customer question or completed project: verify facts, prepare the asset, check the destination and publish only if already authorized and due. Record the actual URL and outcome. If publication is ambiguous, reconcile before retrying. Measure prior content when data is available. Report only meaningful progress, an exception requiring a decision, or a broken enquiry route. Do not invent leads, sales, automation uptime or account access.

A practical starting rhythm for a tiny studio is one bounded daily review and up to two useful social pieces a week. These are workload choices, not platform rules. Choose posting windows from actual audience and team availability; revise from results. A missed slot does not require a batch of catch-up posts.

**What to keep local**

A list of due items, last publication IDs/URLs, source evidence, access constraints and exact outcomes. Use a durable ledger if the same action may be retried across sessions. Keep private enquiries and customer records outside a public Git repo.
