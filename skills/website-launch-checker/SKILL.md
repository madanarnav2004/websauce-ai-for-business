# Check a website before launch

Establish the target URL, main customer action and intended enquiry destination. Read any existing acceptance criteria. Separate the public visitor check from owner-only delivery verification.

Inspect navigation, main CTA, contact links and the enquiry route on desktop and a narrow mobile viewport. Record the actual viewport and observed result; do not infer mobile layout from HTML alone. Check keyboard reachability, visible labels, error feedback and preservation of entered values when relevant tools permit.

An enquiry test needs an authorized destination and clearly synthetic details. Submit once with a unique test reference, then inspect the destination record with matching reference. A thank-you message alone proves only the visible response. If access, bot verification or destination readback is unavailable, mark that check unverified and continue independent checks. Do not bypass verification or submit test leads to an unrelated business.

Return a concise table: check, evidence, pass/fail/unverified, business impact and next action. Separate observed failures from suggestions. Do not claim a security audit, accessibility certification or revenue improvement. Fixes and deployment follow the user's actual request and authorization.
