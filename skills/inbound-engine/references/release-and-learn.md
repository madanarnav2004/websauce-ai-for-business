# Publication and learning

Use when the user asks to publish, a scheduled item is due, or the agent reviews outcomes.

Before submitting, inspect the active account and existing content for duplication. Record an intent with a stable content identifier if a ledger exists. A local due time or draft is not a native schedule. A click on “Share” without a readback is not proof of publication.

After one submission, capture the live URL/provider ID and account. If the action timed out or the UI is ambiguous, do not submit again until the destination has been inspected and the outcome reconciled. Record uncertainty honestly.

At roughly 24 hours and seven days, if data is available, record the post URL, topic, format, publish time, reach, views/plays as defined by the platform, saves/shares, site visits, enquiries, qualified conversations and any observed revenue. Do not treat missing metrics as zero or equate a view, DM or enquiry with a won project. Compare similar posts cautiously and change one hypothesis for the next experiment.

When scheduling an agent run, state the time zone, resource requirements and what happens if the host or account session is unavailable. The run should stop the affected action and continue safe local work; it should not evade platform challenges or retry in a loop.
