# Turn completed work into useful content

Read the supplied project evidence and intended audience. Select one concrete change that helps that audience understand a decision. Check ownership and publication rights; replace private or unapproved customer examples with an explicitly fictional demonstration.

Create a brief identifying audience, observed problem, change, evidence and one next action. Draft the requested asset copy and caption. Keep claims within the evidence: a working form is not proof of more leads; a commit timestamp is not hours worked; a mockup is not a deployed result. Clearly label illustrative or AI-generated representations where relevant.

Provide an evidence note, alt text and a CTA whose destination works. Reuse the user's brand and format rather than inventing a new campaign. If essential proof is missing, revise the claim or mark the asset unready.

Publishing uses the user's actual authorization and account access. Check account identity and recent publications, record intent, submit once, verify the URL and reconcile uncertainty before retrying. Schedule review of actual responses; unknown metrics stay unknown. A queued post is not a published post.
