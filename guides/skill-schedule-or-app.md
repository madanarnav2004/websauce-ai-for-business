# Prompt, skill, schedule or app?

Choose the smallest thing that reliably completes the job.

| If you need… | Start with… | Example |
| --- | --- | --- |
| Help once or a few times | **Prompt** | Draft a clear reply to one customer question. |
| The same judgement and steps each time | **Skill** | Turn completed work into an accurate educational post. |
| A task checked at a regular time | **Schedule** | Review the business inbox each evening and report items needing a decision. |
| A persistent workflow used by people or other systems | **App or cloud service** | Capture enquiries and keep them available even when your laptop is off. |

A skill is instructions and optional resources for an agent. A schedule invokes a task at a time; it does not make a local computer or login permanently available. An app has its own runtime, data and operational costs. These can work together, but adding more layers does not make a weak process useful.

Before moving up a layer, test the task manually. Know the source of truth, what success looks like, and what should happen if a tool times out after a side effect. Keep live sending, publishing, account changes and payments within the access and authority you have actually granted.

For example, Websauce's [inbound engine skill](../skills/inbound-engine/SKILL.md) can prepare content from real work. The [daily run template](../docs/daily-run.md) shows when an agent could return to it. A working website enquiry form is a separate persistent service. None is a substitute for the others.
